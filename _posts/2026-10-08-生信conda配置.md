# 研究背景

现在conda熟练了，也经常会想起当时那段时间，为了装一个冷门的包而耗费了四五天装不上的痛苦。当时我开发了（或者说使用）多种方法，并最终解决了我的问题，用这篇文章分享一下。

### 特别提示

1. 过于冷门的包，装不上也是有原因的；如果一个工具包无issue、无维护、还低分，基本上可以不用，因为师兄说过用了也容易被Argue（我当时费尽心机装上的包最终还是没有用上，等于白干）。

2. 环境中（主要是R）的包尽可能都用conda来，最稳定也是最推荐。经常有说你在R里`install.packages`下载的包和conda环境不适配，报一些奇奇怪怪的错误，总之就是很烦人，尽可能少走弯路，按照顺序来。

# 主要内容

## conda 最推荐

### 1. 配置conda源

首先编辑conda配置文件：

```bash
vim ~/.condarc
```

首先建议你全删掉，保证源的纯净性，一般来说能解决60%以上的问题。

缺点就是，在下载大型包的时候，会容易下载不完/卡顿，容易受到网络波动的影响。

删除完之后清除索引：

```bash
conda clean -i
```

然后就是清华源，直接照着我的源复制粘贴就行，解决90%问题。

**源的配置切忌又多又杂。**

```yaml
channels:
  - http://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud/bioconda/
  - http://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud/menpo/
  - http://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud/msys2/
  - http://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud/conda-forge/
  - http://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud/pytorch/
  - http://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/main/
  - https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/main
  - https://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud/conda-forge
show_channel_urls: true
```

然后搜索你想要的包，记得R包带个`r-`，然后全小写。

这里会提供各个源的各个版本，源分为官方源和社区源，都可以尝试去使用，某些冷门包，社区比官网好用。

## devtools / remotes / pip / Bioconductor / install.packages

这些就是仁者见仁、智者见智环节了。

一般首先看想要的包，作者在git推荐使用什么来下载，然后直接下载就行。

基本上痛点出现在以下几个环节：

### 1. 想要的包和当前环境不适配

两个法子：

- 第一就是把它要求的包降级/升级到指定的版本。这个问题在Seurat出现得还是蛮多的，基本上需要所有的包都自洽才能稳定跑。
- 第二就是换当前包，切版本或者直接切工具，自由取舍。

### 2. 当前环境依赖问题

往往涉及到底层依赖java等。

安装好对应的底层依赖，但是这种问题相对较少。

### 3. 网络或各种原因，下不下来

如果是devtools/remotes，直接下到本地，然后本地安装。

例如：

```r
remotes::install_github("VPetukhov/ggrastr")

devtools::install_local("/BDproject1/-/presto-master.zip")
```

当然R本体也能进行本地安装。

例如，先从下面的地址下载：

```text
https://cran.r-project.org/src/contrib/Archive/vctrs/vctrs_0.7.1.tar.gz
```

然后使用：

```r
install.packages(
  "/BDproject1/-/2_conda_monocle2/vctrs_0.7.1.tar.gz",
  repos = NULL
)
```

### 4. Bioconductor

没遇到过啥特别大的问题，基本上Bioconductor下不了也能走其他的地方下。

### 5. pip

稳定可靠，但是只能Python，可惜。

# 最后的邪道

被折磨了两天写出来的强制下载配置环境法。

## 使用前提

1. 能把源清空最好，不清空的话用清华源可能会出bug。
2. 一次只能配置单个工具的单个环境，不一定能实现一个版本搭载多个包的目标。
3. 适合于网络环境不好、conda下载不下来、其他方法又需要一遍一遍排查依赖的情况。

## 代码原理

先简要介绍一下代码原理：

你只给conda要做的工具的包名，然后conda计算出一套仅供该工具使用的环境依赖体系。

但是网络不好，部分包下不下来（点名批评conda-forge源），所以依照conda给的配置表，我们自己去官网下。

脚本的目的是实现以上内容自动化，并且检查错误（有错误就自己手动下，也不难）。

现在给了v1.1版本，修复了一些小问题。

### 前言

由于最近在整新的生信流程，所以非常需要依赖conda环境来下载包。

但是不幸的是：覆盖面最广、最全、最新的channel——conda-forge寄了。

在选择`-c conda-forge`的时候自动选择的channel：

```text
https://conda.anaconda.org/conda-forge
```

提示页面不存在，但是网页版下载确实一直可以运行：

```text
https://anaconda.org/conda-forge
```

但是要提供一个环境完整运行的所有包，手动下还是太慢了。

基于以下几点，得出结论，可以通过脚本进行自动化下载，并挑选合适的方式方法。

**1. 在使用conda-forge等其他官方channels进行下载时，虽然速度很慢，也会中断，但是在下载之前会给出一个下载的目标清单。**

基于该清单可以得出配置目标环境所需的所有包、版本等信息。

例如：

```text
_libgcc_mutex      conda-forge/linux-64::_libgcc_mutex-0.1-conda_forge
_openmp_mutex      conda-forge/linux-64::_openmp_mutex-4.5-2_gnu
```

**2. 网页版下载的文件和channel中的一致。**

也就是可以实现根据清单信息构建网页版下载链接，再使用wget下载。

例如：

```bash
wget "https://anaconda.org/conda-forge/_libgcc_mutex/0.1/download/linux-64/_libgcc_mutex-0.1-conda_forge.tar.bz2"

wget "https://anaconda.org/conda-forge/_openmp_mutex/4.5/download/linux-64/_openmp_mutex-4.5-2_gnu.tar.bz2"
```

**3. conda包文件有两种后缀。**

分别为较新的`.conda`和较老的`.tar.bz2`。

而且在构筑好目标链接后，可以查询文件是否存在，以此排除文件后缀差异的干扰。

# 关键代码

## 1_Download_v1.1.sh

通用强制下载方法。

- 日期：2025-09-14
- 位置：`/BDproject1/User/zhouchi/tools/conda_install`
- v1.1：修改了default渠道的支持项，详见“1. Maestro下载_强制下载法”。

```bash
#!/bin/bash

# 用法: ./generate_download_urls.sh package_list.txt
# 其中 package_list.txt 是包含conda包列表的文件
# v1.1: 修改了default渠道的支持项

INPUT_FILE="$1"

if [ ! -f "$INPUT_FILE" ]; then
    echo "错误: 文件 $INPUT_FILE 不存在!"
    exit 1
fi

# 定义输出文件
SUCCESS_FILE="download_urls.sh"
FAILURE_FILE="failed_urls.txt"
DOWNLOAD_DIR="Download"

echo "开始处理文件: $INPUT_FILE"
echo "成功的下载命令将保存到: $SUCCESS_FILE"
echo "失败的URL将保存到: $FAILURE_FILE"

# 初始化输出文件
echo "#!/bin/bash" > "$SUCCESS_FILE"
chmod +x "$SUCCESS_FILE"
> "$FAILURE_FILE"

# 计数器
COUNT=0
SUCCESS_COUNT=0
FAILURE_COUNT=0

# 处理文件的每一行
while IFS= read -r line; do

    # 跳过空行和注释行
    if [[ -z "$line" || "$line" == \#* ]]; then
        continue
    fi

    # 提取关键信息
    second_part=$(echo "$line" | awk '{print $2}')

    IFS="::" read -r channel_platform filename <<< "$second_part"

    channel="${channel_platform%/*}"
    platform="${channel_platform##*/}"

    original_filename=$(echo "$filename" | tr -d ':\n')

    version=$(echo "$original_filename" | sed -nE 's/.*-([^-]*)-[^-]*$/\1/p')

    if [[ -z "$version" ]]; then
        version="unknown"
    fi

    package=$(echo "$original_filename" | sed -E 's/(.*)-.*-.*$/\1/')

    # 构建可能的文件名
    filename1="${original_filename}.conda"
    filename2="${original_filename}.tar.bz2"

    if [[ "$channel" =~ / ]]; then

        # 构建官方仓库链接
        url1="https://repo.anaconda.com/${channel}/${platform}/${filename1}"
        url2="https://repo.anaconda.com/${channel}/${platform}/${filename2}"

    else

        # 构建Anaconda.org下载链接
        url1="https://anaconda.org/${channel}/${package}/${version}/download/${platform}/${filename1}"
        url2="https://anaconda.org/${channel}/${package}/${version}/download/${platform}/${filename2}"

    fi

    echo "检查包: $package" >&2

    # 尝试.conda格式
    if curl --output /dev/null --silent --head --fail "$url1"; then

        echo "wget \"$url1\"" >> "$SUCCESS_FILE"

        SUCCESS_COUNT=$((SUCCESS_COUNT + 1))

        echo "找到: $url1" >&2

    # 尝试.tar.bz2格式
    elif curl --output /dev/null --silent --head --fail "$url2"; then

        echo "wget \"$url2\"" >> "$SUCCESS_FILE"

        SUCCESS_COUNT=$((SUCCESS_COUNT + 1))

        echo "找到: $url2" >&2

    else

        # 两个URL都失败
        echo "$url1" >> "$FAILURE_FILE"
        echo "$url2" >> "$FAILURE_FILE"

        FAILURE_COUNT=$((FAILURE_COUNT + 1))

        echo "警告: 无法找到包 $package 的下载链接" >&2

    fi

    COUNT=$((COUNT + 1))

    # 添加短暂延迟
    sleep 0.1

done < "$INPUT_FILE"

# 所有查询结束后创建Download文件夹
mkdir -p "$DOWNLOAD_DIR"

echo "创建下载目录 $DOWNLOAD_DIR"

# 输出结果
echo "处理完成!"
echo "总共处理: $COUNT 个包"
echo "成功找到: $SUCCESS_COUNT 个下载链接 (命令已存入 $SUCCESS_FILE)"
echo "失败: $FAILURE_COUNT 个包 (URL已存入 $FAILURE_FILE)"

# 尝试进入Download目录并执行下载脚本
if cd "$DOWNLOAD_DIR"; then

    echo "正在进入目录 $DOWNLOAD_DIR 并执行下载脚本..."

    if bash "../$SUCCESS_FILE"; then

        echo "下载脚本执行完毕。"

    else

        echo "警告: 下载脚本执行过程中可能出现了错误。"

    fi

else

    echo "错误: 无法进入目录 $DOWNLOAD_DIR"

    exit 1

fi
```

## 2_Install_v1.1.sh

```bash
#!/bin/bash

# 激活Conda环境
conda activate tools_sceasy

# 定义目标目录
target_dir="./Download"

# 检查目标目录是否存在
if [ ! -d "$target_dir" ]; then

    echo "错误: 目录 $target_dir 不存在。"

    exit 1

fi

# 切换到目标目录
cd "$target_dir" || exit 1

echo "开始优先处理 'r-base-*' 和 'python-*' 文件..."

# 优先处理模式1: r-base-*
for file in r-base-*; do

    if [ -f "$file" ]; then

        file_abs_path=$(realpath "$file")

        echo "正在优先处理 r-base 文件: $file_abs_path"

        conda install --use-local "$file_abs_path"

    fi

done

# 优先处理模式2: python-*
for file in python-*; do

    if [ -f "$file" ]; then

        file_abs_path=$(realpath "$file")

        echo "正在优先处理 python 文件: $file_abs_path"

        conda install --use-local "$file_abs_path"

    fi

done

echo "开始处理其他文件..."

# 排除已处理的优先文件模式
GLOBIGNORE="r-base-*:python-*"

for file in *; do

    if [ -f "$file" ]; then

        file_abs_path=$(realpath "$file")

        echo "正在处理其他文件: $file_abs_path"

        conda install --use-local "$file_abs_path"

    fi

done

# 取消GLOBIGNORE
unset GLOBIGNORE

echo "所有文件处理完成。"
```
